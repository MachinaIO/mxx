## User decisions that override or refine the plan

- Prefer a simple implementation and avoid new types, traits, functions, files, allocators, schedulers, or duplicate ownership/state unless needed for correctness. In particular, one owner should define a physical layout/stride; compact matrix format should be unified, not converted between competing formats. Remove old routes rather than preserve compatibility scaffolding.
- Use OpenFHE/OpenFHE-rs where the project still depends on it, including CRT modulus generation. Do not introduce a bespoke generator merely to remove a dependency. CPU `small=true` coefficients must be balanced.
- Planning should place production-equivalent data and trial candidate `W,C` pairs within available VRAM, rather than rely on an elaborate predictive memory formula or a hard 80% limit. Among feasible pairs choose the one with minimum predicted execution time. Keep GPU allocations and reuse dependencies explicit; do not require exact 80% enforcement.
- For artifact writes, assume enough distinct slots for one execution, allocate them before launch, and request file writes promptly as each slot becomes ready. GPU execution must not wait for disk completion or insert a host check/Graph split on every write. Failed allocation is an explicit planning/resource error. Never preload every artifact: load only a reached selected artifact/chunk when needed.
- A plan may be reused sequentially with different inputs and nonce. A subsequent `execute` **may invalidate every previous returned output**. The caller must copy, download, or save any needed result before the next call. Expose outputs as a borrow from the plan so Rust prevents a live result from overlapping the next execution; do not expose a cloneable resident owner through that API. Trapdoor gets no special previous-return retention. Inputs/intermediates can be recycled after their last GPU read/transfer, with proper Graph/event dependencies. Artifact slot lifetime remains tied to its asynchronous file consumer.
- No primitive may silently use CPU fallback; no valid `NodeKind` may remain unconnected. Use exhaustive dispatch without a catch-all `Err` for new variants, and verify the actual production path with GPU tests. Compile-time exhaustiveness does not establish semantic correctness.
- For future collaboration, assign agents coherent **end-to-end problems** rather than fixed architectural layers, while reserving ownership of shared files to avoid concurrent edit conflicts. The user requested a pause now, so do not restart workers until asked to resume.
